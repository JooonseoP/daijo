# 다잊어 MVP — 핵심 루프 설계 (Android)

- **작성일**: 2026-09-16 (2026-09-17 스펙 리뷰 확정)
- **상태**: 스펙 리뷰 완료 / 구현 계획 작성 단계
- **서브프로젝트**: 1 / 5 (핵심 루프). 전체 앱은 5개 독립 서브시스템으로 분해됨 — 아래 "전체 로드맵" 참고.
- **근거 문서**: `lib/다잊어(Daiso Reminder) - 위치 기반 쇼핑 리마인더 앱 기획 및 기술 명세서.docx` (사전 브레인스토밍)

## 배경

매장 입구를 지나는 순간 사려던 목록을 잊는 인지적 현상(출입문 효과, 맥락 의존 기억, 미래 계획 기억 실패)을 **위치 트리거**로 해결하는 지오펜싱 쇼핑 리마인더. 사용자가 살 물건을 적어두면, 다이소 매장 반경 진입 시 목록을 알림으로 강제 노출한다.

## 이번 사이클의 범위

핵심 루프만 구현한다.

- 쇼핑 아이템 **추가/수정/삭제/완료 체크** (이름 + 수량 + 등록시각), 로컬 영구 저장
- 앱 첫 실행 시 번들 JSON에서 **매장 좌표 시드 → DB 적재**
- 현재 위치 기준 **가까운 매장 N개에 지오펜스 등록** (OS 100개 제한 내)
- 매장 반경 **진입(ENTER) 시 로컬 알림** — 현재 쇼핑 목록 요약 노출
- 알림 탭 → 앱의 목록 화면으로 진입
- **권한 온보딩** — 위치("항상 허용")·알림 권한 안내 및 요청

### 명시적 비범위 (다음 사이클, YAGNI)

- 인앱 매장 모드 (한 손 조작 UI, 햅틱, 완료 애니메이션)
- 스테디셀러 사전 자동완성 · 개인 히스토리 추천
- 아카이브 / 과거 내역 재등록
- 백업·복원 (JSON/CSV, Google Drive/iCloud)
- 동적 지오펜스 재등록 고도화 (significant-motion 기반 반경 5~10km 재선별)
- iOS 및 데스크톱/웹

## 결정 사항 (브레인스토밍 확정)

| 항목 | 결정 |
| --- | --- |
| 첫 빌드 범위 | 핵심 루프 MVP만 |
| 타겟 플랫폼 | Android 먼저 |
| 매장 좌표 데이터 | 씨드 JSON 번들 내장 (`assets/data/stores_seed.json`), 첫 실행 시 로컬 DB 적재. 추후 전국 데이터로 교체 가능 |
| 상태관리 | Riverpod |
| 로컬 DB | Drift (SQLite) — 타입 세이프, 테스트 시 in-memory |
| 알림 | flutter_local_notifications |
| 지오펜싱 플러그인 | **`native_geofence` 확정** — OS 네이티브 Geofencing API 래핑, 백그라운드 콜백, 무료. 명세서가 언급한 `flutter_background_geolocation`은 백그라운드가 상용 라이선스라 MVP에서 제외 |
| 가까운 매장 N | **20개 확정** — 앱 실행 시마다 현재 위치 기준 가까운 20개를 재선별해 지오펜스 재등록 |
| 지오펜스 반경 | **150m 확정** |
| 시드 데이터 | **테스트용 소수(5~10개) + 스키마 확정** — 전국 데이터는 추후 교체 |
| 권한 | permission_handler / geolocator |

## 아키텍처 (feature-first)

```
lib/
  main.dart              앱 진입, ProviderScope, 초기화
  app.dart               MaterialApp, 라우팅
  core/
    db/                  Drift database + 테이블 정의
    notifications/       NotificationService (인터페이스 + 구현)
    geofence/            GeofenceService (인터페이스 + 구현)
    location/            권한 + 현재 위치 취득
  features/
    shopping_list/
      data/              DAO / repository
      domain/            model (ShoppingItem)
      presentation/      화면 · 위젯 · Riverpod provider/controller
    stores/
      data/              시드 로더 · store repository
      domain/            model (Store)
      application/       GeofenceManager (가까운 N개 선별 · 등록)
assets/
  data/stores_seed.json
```

**설계 원칙**: 알림·지오펜스·위치 등 플랫폼 서비스는 **인터페이스 뒤에 격리**하여 테스트에서 목(mock) 주입이 가능하도록 한다. 각 유닛은 단일 책임을 가지며 잘 정의된 인터페이스로 통신한다.

## 데이터 흐름

1. 앱 시작 → Drift DB 초기화
2. (첫 실행) 시드 JSON 로드 → `stores` 테이블 적재
3. 권한 요청 (위치 "항상 허용" + 알림)
4. `GeofenceManager`가 현재 위치 기준 가까운 N개 매장 선별 → 지오펜스 등록
5. 네이티브 지오펜싱이 백그라운드로 감시
6. **ENTER 이벤트** 발생 → `NotificationService`가 현재 목록 요약 알림 생성
7. 사용자가 알림 탭 → 앱의 쇼핑 목록 화면으로 진입

※ 목록이 비어 있으면 알림하지 않는다.

## 데이터 모델 (초안)

- **ShoppingItem**: `id`, `name`, `quantity`, `isDone`, `createdAt`
- **Store**: `id`, `name`, `latitude`, `longitude`, `radius`(기본값 있음)

(향후 아카이브/히스토리 확장을 고려해 필드를 최소하되 전방 호환적으로 유지)

## 오류 처리

- **위치/알림 권한 거부** → 온보딩에서 필요성 설명. 앱은 **순수 목록 앱으로는 계속 사용 가능**하며, 지오펜싱 비활성 상태를 배너로 표시.
- **백그라운드 위치 미허용** → 포그라운드 한정 동작 안내.
- **지오펜스 등록 실패** → 로깅 + 상태 표시, 앱 크래시 없이 저하 동작.

## 테스트 전략 (TDD)

기기 없이 검증 가능한 로직을 인터페이스 뒤로 분리한다.

- 아이템 repository CRUD (in-memory Drift)
- 시드 JSON 파싱/적재
- 가까운 N개 매장 선별 로직 (거리 계산)
- 알림 페이로드 빌더
- 지오펜스/알림 서비스는 인터페이스 목으로 상호작용 검증
- 실제 지오펜스 트리거는 기기 수동 테스트 (에뮬레이터 GPS 주입 활용)

## 전체 로드맵 (참고 — 이후 사이클)

각 서브프로젝트는 독립적으로 스펙 → 계획 → 구현 사이클을 가진다.

1. **핵심 루프 (본 문서)**
2. 매장 인앱 모드
3. 스마트 입력 (스테디셀러 사전 + 개인 히스토리)
4. 아카이브 & 재등록
5. 백업 & 복원 (로컬 파일 + 클라우드)
